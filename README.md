Conference Management System (Lab 4: Basic Security & RBAC)
📌 Описание проекта

Серверная часть (REST API) системы управления научными конференциями. Проект предназначен для автоматизации процессов организации мероприятий: создания расписания, регистрации участников и контроля загруженности залов. В рамках 4-й лабораторной работы в проект интегрирована система безопасности на основе ролевой модели доступа и полноценная работа с базой данных PostgreSQL.

🛠 Технологический стек

Язык: Java 21

Фреймворк: Spring Boot 3.5.9

База данных: PostgreSQL

ORM: Hibernate / Spring Data JPA

Безопасность: Spring Security 6 (Basic Auth)

Сборка: Maven

Библиотеки: Lombok, ModelMapper

🔐 Архитектура безопасности (Lab 4)

В проекте реализована классическая многоуровневая система защиты доступа.

1. Аутентификация

Используется протокол HTTP Basic Auth. Доступ к любым ресурсам API (кроме регистрации) требует передачи закодированных учетных данных в заголовке запроса.

2. Ролевая модель (RBAC)

В системе определены две основные роли:

ROLE_ADMIN: Имеет полные права на управление данными. Может создавать (POST), изменять (PUT) и удалять (DELETE) мероприятия, сессии, участников и спикеров.

ROLE_USER: Имеет право на чтение данных (GET) и выполнение базовых операций, таких как просмотр программы конференции или получение информации о своей регистрации.

3. Защита учетных данных

Хэширование: Пароли пользователей не хранятся в открытом виде. Используется алгоритм BCrypt для генерации надежных хэш-сумм.

Валидация: При регистрации реализована проверка сложности пароля. Пароль должен быть не менее 8 символов и содержать хотя бы один специальный символ (!@#$%^&* и др.).

🗂 Структура Базы Данных

Система оперирует 7 основными таблицами в PostgreSQL:

Events — Информация о конференциях (название, даты, локация).

Sessions — Доклады и секции внутри мероприятия (время начала/конца, лимит мест).

Participants — Данные зарегистрированных участников.

Speakers — Информация о докладчиках и их биографии.

Registrations — Связующая таблица (Участник ↔ Сессия) со статусами подтверждения.

App_Users — Учетные записи для входа в систему.

Roles — Справочник ролей доступа.

💼 Бизнес-операции (Logic)

Реализовано 5 транзакционных сценариев, затрагивающих несколько сущностей:

Регистрация на сессию (POST /api/registrations/register) — Создание записи участника с автоматической проверкой лимита мест в зале.

Умная проверка конфликтов — Система автоматически блокирует регистрацию, если у участника уже есть другая сессия в это же время.

Динамический пересчет мест — При создании или отмене (CANCELLED) регистрации счетчик currentParticipants в таблице сессий обновляется автоматически.

Управление спикерами — Назначение спикера на доклад с проверкой его доступности в выбранный временной интервал.

Каскадное управление — При удалении мероприятия автоматически аннулируются все связанные с ним сессии и регистрации.

🚀 Инструкция по запуску и тестированию
1. Настройка окружения

Перед запуском необходимо задать переменные окружения для подключения к вашей базе данных PostgreSQL:

DB_USERNAME = ваш_логин

DB_PASSWORD = ваш_пароль

2. Регистрация пользователей

Так как база данных изначально пуста, необходимо создать учетные записи через API:

POST /api/auth/register-admin — для создания администратора.

POST /api/auth/register — для создания обычного пользователя.

3. Тестирование в Postman

Откройте любой защищенный эндпоинт (например, GET /api/events).

Перейдите на вкладку Authorization.

Выберите тип Basic Auth.

Введите логин и пароль зарегистрированного пользователя.

Для проверки прав ADMIN попробуйте выполнить DELETE запрос. Если войти под обычным USER, система вернет ошибку 403 Forbidden.
